# 技术简洁审查知识库（CloudPan）

> 供任务产生者 task-producer 及其技术简洁审查子 Agent 使用。判据：最少代码、最少依赖、最少抽象。

## 1. 核心原则

- **YAGNI**：不为推测性需求写代码
- **KISS**：最简单可行的方案
- **SRP**：一个类/方法一个职责
- **最少依赖**：能不加包就不加，能用框架原生就用
- **删除优先**：删除 > 简化 > 合并 > 添加

## 2. 过度工程信号（发现即报）

- 为一次性代码建抽象层/接口
- 不必要的泛型、反射、动态代码
- 造已有库/框架的轮子（如手写日志、配置、序列化）
- 多余项目、多余 NuGet 包
- 配置项/开关超过实际需要
- 不必要的设计模式（为一个变化点建策略/工厂/抽象基类）
- 用异步/并发解决本可顺序解决的简单问题

## 3. 重复与冗杂

- 相同逻辑多处复制（应抽取）——但避免"为一个调用点抽取"的过度抽象
- 长方法、深嵌套、长参数列表
- 死代码、注释掉的代码、未使用的 using/引用/字段

## 4. 简洁性量化判据

- 单类 ≤ 400 行
- 方法 ≤ 30 行（倾向）
- 嵌套 ≤ 3 层
- 参数 ≤ 4 个（倾向用对象聚合）
- 依赖：能减一个就减一个

## 5. 审查问题清单

- [ ] 这段代码有真实使用者吗？删掉会怎样？
- [ ] 抽象层是否有 ≥2 个实际场景支撑？
- [ ] 有没有可用的现成方案被手写代替？
- [ ] 有没有可删除的依赖 / 项目 / 配置？
- [ ] 复杂度源于问题本身，还是自造？
