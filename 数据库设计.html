CloudPan 数据库设计

SQLite 表结构与索引规范

版本 1.2 2026-07-28 引擎：SQLite 3.x (WAL 模式) ORM：Entity Framework Core 8

1. 概述

1.1 数据库文件

服务端{SyncRoot}/.cloudpan/server.db — 文件索引、版本链、设备注册、分享记录
Windows 客户端%LocalAppData%/CloudPan/client.db — 远程快照、同步游标、待传输队列
Android 客户端/data/data/.../databases/cloudpan.db (Room) — 本地缓存清单、下载状态

1.2 全局配置

WAL 模式PRAGMA journal_mode=WAL; — 支持并发读写，崩溃恢复更强
外键PRAGMA foreign_keys=ON; — 保证引用完整性
同步模式PRAGMA synchronous=NORMAL; — WAL 下安全且性能较好

2. 实体关系

3. 服务端表

3.1 FileEntry — 文件条目

服务端权威文件索引。每行 = 一个文件或目录。使用相对路径作为主键。

列名类型约束说明
PathTEXTPK相对同步根的路径。以 / 开头，如 "/docs/report.docx"。目录以 / 结尾，如 "/docs/"
TypeINTEGERNOT NULL0=File, 1=Directory
CurrentHashTEXT—当前版本 SHA-256（64 字符十六进制）。目录为 NULL
CurrentSizeINTEGERNOT NULL DEFAULT 0当前版本字节数。目录为 0
VersionINTEGERNOT NULL DEFAULT 1当前版本号，全局单调递增。服务端分配
LastModifiedTEXTNOT NULLISO 8601 UTC 时间戳
StateINTEGERNOT NULL DEFAULT 00=Synced, 1=Modified, 2=Deleting, 3=CloudOnly, 4=Downloading, 5=Uploading, 7=Conflict
CreatedAtTEXTNOT NULL首次创建时间（UTC）

索引

CREATE INDEX idx_fileentry_state ON FileEntry(State); CREATE INDEX idx_fileentry_type ON FileEntry(Type); CREATE INDEX idx_fileentry_version ON FileEntry(Version);

注：ParentPath 由应用层从 Path 推导（截断最后一段），无需显式存储列及索引。目录子节点查询使用 LIKE 前缀匹配。删除文件夹时应用层递归处理子文件。

3.2 VersionRecord — 版本历史

文件每次修改产生一条记录。保留最近 N 个版本（默认 5），超出的由后台任务清理。

列名类型约束说明
IdINTEGERPK AUTOINCREMENT自增主键
FilePathTEXTFK→FileEntry(Path) NOT NULL关联文件
VersionINTEGERNOT NULL该记录对应的版本号
HashTEXTNOT NULL该版本 SHA-256
SizeINTEGERNOT NULL该版本字节数
StoragePathTEXTNOT NULL版本文件在 .versions/ 中的路径（如 ".versions/report_v12_20260727.docx"）
TimestampTEXTNOT NULL版本创建时间（UTC）
DeviceIdTEXTFK→Device(Id) NOT NULL哪个设备创建了此版本
RestoredFromVersionINTEGER—回滚操作专属：回滚自哪个版本号。普通上传为 NULL

索引

CREATE INDEX idx_version_file  ON VersionRecord(FilePath, Version DESC);
CREATE INDEX idx_version_device ON VersionRecord(DeviceId);
CREATE INDEX idx_version_ts      ON VersionRecord(Timestamp);

版本清理（后台任务）

-- 每个文件保留最新 N 个版本（默认 5），删除超出版本 + 对应磁盘文件
DELETE FROM VersionRecord
WHERE Id NOT IN (
    SELECT Id FROM VersionRecord
    WHERE FilePath = @path
    ORDER BY Version DESC
    LIMIT @maxVersions
) AND FilePath = @path;
不要忘记删除磁盘文件：清理 VersionRecord 行前，先读取 StoragePath 并删除对应的 .versions/ 文件。

3.3 Device — 设备注册

列名类型约束说明
IdTEXTPK设备唯一标识（客户端首次连接时生成，GUID 格式）
NameTEXTNOT NULL用户可读名称（如"张三的笔记本"）
PersonTEXT—设备所属人。仅展示用，不参与权限
LastSeenTEXTNOT NULL最后在线时间（UTC）
OnlineINTEGERNOT NULL DEFAULT 00=离线, 1=在线（WebSocket 连接状态）
RegisteredAtTEXTNOT NULL首次注册时间

3.4 Share — 分享链接

列名类型约束说明
IdTEXTPK分享 ID（32 字符十六进制随机字符串）
FilePathTEXTNOT NULL分享的文件路径
PasswordHashTEXT—密码的 SHA-256。NULL = 无密码
ExpiresAtTEXT—过期时间（UTC）。NULL = 永不过期
MaxDownloadsINTEGER—最大下载次数。NULL = 不限
UsedDownloadsINTEGERNOT NULL DEFAULT 0已使用下载次数
CreatedAtTEXTNOT NULL创建时间
CreatedByTEXTNOT NULL创建设备 ID

过期清理

-- 启动时或定时任务执行
DELETE FROM Share
WHERE ExpiresAt IS NOT NULL AND ExpiresAt < @now
   OR (MaxDownloads IS NOT NULL AND UsedDownloads >= MaxDownloads);

索引

CREATE INDEX idx_share_filepath ON Share(FilePath);
	CREATE INDEX idx_share_expires   ON Share(ExpiresAt);
	CREATE INDEX idx_share_created   ON Share(CreatedAt);

3.5 AppConfig — 服务端配置

键值对存储，用于 Token 哈希、证书指纹等全局配置。

列名类型约束说明
KeyTEXTPK配置键
ValueTEXTNOT NULL配置值

预定义键

token_hashSHA-256(家庭Token)
cert_fingerprint自签证书 SHA-256 指纹
max_versions保留版本数（默认 "5"）
scan_interval_minutes定时扫描间隔（默认 "5"）
server_version服务端版本号
global_version全局单调版本号计数器（每次文件变更 +1）

3.6 ChunkedUpload — 分块上传状态

追踪大文件分块上传的中间状态。全部块接收并合并完成后删除此记录。超时未完成的上传由后台任务清理。

列名类型约束说明
FilePathTEXTPK目标文件路径
DeviceIdTEXTNOT NULL发起上传的设备 ID。用于区分多设备同时上传同一文件
FileHashTEXTNOT NULL完整文件 SHA-256（去重和完整性校验依据）
TotalChunksINTEGERNOT NULL总块数
ReceivedChunksTEXTNOT NULLJSON 数组，已收到的块索引列表，如 [0,1,3]
TempPathTEXTNOT NULL合并前的临时文件路径（.tmp）
BaseVersionINTEGERNOT NULL上传基准版本号
LastModifiedTEXTNOT NULL文件最后修改时间
CreatedAtTEXTNOT NULL首块到达时间。用于清理超时未完成的上传

索引

CREATE INDEX idx_chunk_created ON ChunkedUpload(CreatedAt);
清理策略：后台任务（每 60 分钟执行）删除 CreatedAt 超过 chunkedUploadTimeoutMinutes（默认 1440 分钟 = 24h）的记录，同时清理对应的 TempPath 临时文件。客户端断点续传时，通过 GET /api/files/upload/chunk/status 查询 missingChunks 即可恢复。

3.7 SyncLog — 同步操作日志

P2 阶段新增。记录每次文件同步操作的审计信息。

列名类型约束说明
IdINTEGERPK AUTOINCREMENT自增主键
FilePathTEXTNOT NULL文件路径
OperationINTEGERNOT NULL0=Upload, 1=Download, 2=Delete, 3=Rename, 4=Restore
DeviceIdTEXTNOT NULL操作来源设备
ResultINTEGERNOT NULL0=Success, 1=Conflict, 2=Error
DetailsTEXT—附加信息（如冲突文件路径、错误详情）
CreatedAtTEXTNOT NULL操作时间
CREATE INDEX idx_log_time ON SyncLog(CreatedAt DESC);
CREATE INDEX idx_log_file  ON SyncLog(FilePath);

3.8 缩略图存储

缩略图不存数据库。服务端在 {SyncRoot}/.thumbnails/ 目录下按原路径结构缓存 JPEG 文件（如 .thumbnails/photos/img001_200.jpg，后缀为尺寸）。首次请求时生成，后续直接返回文件。源文件删除时清理对应缩略图。

4. 客户端表（Windows & Android）

4.1 SyncQueue — 待传输队列

持久化存储。客户端重启后队列不丢失。FIFO 处理，小文件优先。

列名类型约束说明
IdINTEGERPK AUTOINCREMENT自增主键
FilePathTEXTNOT NULL文件路径
OperationINTEGERNOT NULL0=Upload, 1=Download, 2=Delete
PriorityINTEGERNOT NULL DEFAULT 00=Normal, 1=High（小文件：<1MB）
BaseVersionINTEGER—操作基于的版本号（用于冲突检测）
FileSizeINTEGER—文件大小（用于进度估算）
RetryCountINTEGERNOT NULL DEFAULT 0已重试次数
LastErrorTEXT—最后一次错误信息
CreatedAtTEXTNOT NULL入队时间。FIFO 排序依据（小文件优先于同时间的大文件）
CREATE INDEX idx_queue_sort ON SyncQueue(Priority DESC, CreatedAt ASC);

4.2 RemoteSnapshot — 服务端文件树快照

客户端本地缓存的服务端文件列表。用于离线比对和增量同步依据。

列名类型约束说明
PathTEXTPK文件路径（与服务端 FileEntry.Path 对应）
TypeINTEGERNOT NULL0=File, 1=Directory
HashTEXT—缓存的哈希值
SizeINTEGERNOT NULL DEFAULT 0缓存的字节数
VersionINTEGERNOT NULL DEFAULT 0缓存的版本号
StateINTEGERNOT NULL DEFAULT 0本地状态：0=Synced, 3=CloudOnly, 4=Downloading, 5=Uploading

4.3 SyncCursor — 同步游标

记录客户端已同步到的位置。单行表。

列名类型约束说明
IdINTEGERPK DEFAULT 1固定为 1（单行）
LastMaxVersionINTEGERNOT NULL DEFAULT 0上次同步到的服务端全局版本号。用于 sinceVersion 增量拉取
LastSyncAtTEXT—上次成功同步时间

4.4 Android 附加表

BackupLog — 照片备份记录

列名类型约束说明
IdINTEGERPK AUTOINCREMENT自增
LocalUriTEXTNOT NULL本地 MediaStore URI
RemotePathTEXTNOT NULL上传后的服务端路径（如 /Photos/小明的手机/IMG_001.jpg）
FileHashTEXTNOT NULL文件 SHA-256（去重：同哈希不上传）
FileSizeINTEGERNOT NULL字节数
StatusINTEGERNOT NULL DEFAULT 0BackupStatus 枚举：0=Pending, 1=Uploading, 2=Done, 3=Failed
CreatedAtTEXTNOT NULL记录创建时间

OfflineCache — 离线收藏

列名类型约束说明
PathTEXTPK文件路径
LocalPathTEXTNOT NULL本地缓存文件的绝对路径
FileHashTEXTNOT NULL缓存版本的哈希（用于判断是否需要更新）
FileSizeINTEGERNOT NULL字节数
CachedAtTEXTNOT NULL缓存时间

5. 迁移策略

5.1 EF Core 迁移

使用 EF Core Code-First 管理表结构变更。每次发布时附带自动迁移。

// 启动时
using var db = new CloudPanDbContext();
await db.Database.MigrateAsync();  // 自动应用未执行的迁移

5.2 迁移规则

可安全执行新增表、新增列（带 DEFAULT）、新增索引
需谨慎删除列、重命名列、修改列类型 — SQLite 不支持 ALTER COLUMN。需重建表
禁止生产环境手工改表。所有表结构变更必须通过 EF Core Migration

5.3 数据完整性检查

服务端启动时执行：

-- 1. 检查 SQLite 完整性
PRAGMA integrity_check;

-- 2. 清理孤儿 VersionRecord（FileEntry 不存在）
DELETE FROM VersionRecord
WHERE FilePath NOT IN (SELECT Path FROM FileEntry);

-- 3. 清理过期分享链接
DELETE FROM Share
WHERE (ExpiresAt IS NOT NULL AND ExpiresAt < datetime('now'))
   OR (MaxDownloads IS NOT NULL AND UsedDownloads >= MaxDownloads);

6. 常用查询模式

6.1 增量文件树（sinceVersion）

SELECT Path, Type, CurrentHash, CurrentSize, Version, LastModified, State
FROM FileEntry
WHERE Version > @sinceVersion
ORDER BY Version ASC
LIMIT @limit;

6.2 分页文件树（cursor）

SELECT Path, Type, CurrentHash, CurrentSize, Version, LastModified, State
FROM FileEntry
WHERE Path > @cursor
ORDER BY Path ASC
LIMIT @limit;

6.3 子目录列表

-- 列出 /docs/ 下的直接子文件和子目录
SELECT *
FROM FileEntry
WHERE Path LIKE '/docs/%'
  AND Path NOT LIKE '/docs/%/%';

6.4 版本历史

SELECT v.Version, v.Hash, v.Size, v.StoragePath, v.Timestamp, d.Name AS DeviceName
FROM VersionRecord v
JOIN Device d ON v.DeviceId = d.Id
WHERE v.FilePath = @path
ORDER BY v.Version DESC
LIMIT @maxVersions;

6.5 去重检查

-- 上传前：检查是否已有相同哈希的文件（可选，用于跨文件去重）
SELECT Path FROM FileEntry
WHERE CurrentHash = @hash AND CurrentSize = @size
LIMIT 1;

6.6 全局版本号递增

-- 原子获取下一个版本号
UPDATE AppConfig SET Value = CAST(Value AS INTEGER) + 1
WHERE Key = 'global_version';
SELECT Value FROM AppConfig WHERE Key = 'global_version';
并发安全：SQLite 在 WAL 模式下，写操作是串行的。单个 UPDATE + SELECT 在同一个事务中执行，保证原子性。多客户端并发请求会被 SQLite 的写锁自动排队。
