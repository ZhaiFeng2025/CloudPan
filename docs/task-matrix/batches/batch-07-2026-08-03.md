### F-115 [功能 / P1] CloudPan.Client.Core/Services/ApiClient.ThrottledStream.cs:44-76,78-92

- **问题**：限速流在配额耗尽/首次调用时返回 0，被 CopyToAsync 当作 EOF 提前终止→限速下载/上传被截断。ReadAsync 中 allowed = (int)Math.Min(count, maxBytes - _bytesThisTick)，当 elapsed 极小（构造后立即 CopyToAsync 同一 tick 内）或 _bytesThisTick 追上 maxBytes（每秒配额耗尽）时 allowed<=0 → await Task.Delay(10); return 0（71 行）。CopyToAsync 覆写循环 while ((bytesRead = await ReadAsync(...)) > 0)（88 行）把返回 0 当 EOF 直接退出。UploadAsync 与 DownloadAsync 均经此流：设置任意限速后，大文件（>限速值/秒）下载在配额边界截断→哈希校验失败→10 次阶梯退避全部截断→下载永久失败；上传截断→multipart 不完整→服务端解析异常或保存不完整文件。T-063 刚把限速做成运行时热更新，限速流本体确定性 bug 使限速功能整体不可用。

### T-073 修复限速流配额边界返回 0 被当 EOF 截断（ThrottledStream 重试读 + 单测）（P1 / 功能）

- **来源**：F-115 @ CloudPan.Client.Core/Services/ApiClient.ThrottledStream.cs:44-76,78-92
- **范围**：CloudPan.Client.Core/Services/ApiClient.ThrottledStream.cs（Read/ReadAsync/CopyToAsync）
- **依赖**：无
- **目标**：开启限速后任意大小文件下载/上传完整到达，配额边界不截断，限速功能主路径可用
- **需求**：
  - ThrottledStream.ReadAsync/Read 在配额耗尽（allowed<=0）时改为等待后重新计算配额并重试读取（循环直到 elapsed 允许新字节或底层流返回 0），不再 return 0 表示配额等待
  - 明确区分『配额等待』与『底层流 EOF』：仅底层流返回 0 才向 CopyToAsync 传播 EOF，节流等待走 sleep 后重试读
  - 补限速流单测：限速 10KB/s 读取 1MB 文件完整到达且内容一致；同一 tick 内连续多次调用不截断
- **验收标准**：
  - [自动] 单测覆盖限速流 1MB 文件完整读出不截断且内容一致（dotnet test --filter ThrottledStream）
