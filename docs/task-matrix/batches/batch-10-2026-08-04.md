### F-157 [UX / P2] FileListScreen.kt:73-81（formatTimestamp 用 SimpleDateFormat("yyyy-MM-dd'T'HH:mm:ss") 无时区解析）；SettingsScreen.kt:550-558（同解析）+ :527（设备最后在线）；服务端 FileIndexService.cs:346（DateTime.UtcNow.ToString("O")，含小数秒+Z）；对照 VersionHistoryDialog.cs:172-182（AdjustToUniversal+ToLocalTime 正确换算）

- **问题**：服务端把文件/设备时间存为 ISO 8601 "O" 格式（含小数秒与 Z），Android 两端 formatTimestamp 用 SimpleDateFormat("yyyy-MM-dd'T'HH:mm:ss")（无毫秒无时区）解析，lenient 模式把时间戳前缀按设备本地时区读取并忽略 ".1234567Z"，从不换算 UTC→本地；家庭局域网（UTC+8）下文件「修改时间」与设备「最后在线」恒显示早 8 小时的 UTC 时钟值（本地 22:23 的文件显示 14:23）。
- **为何阻碍使命**：按时间找最近照片/文件是家庭高频路径，Android 显示错误时间直接误导用户；违反 ux-kb『系统与真实世界匹配』与 visual-kb『两平台行为一致』，同一函数同时污染文件列表与设备列表两处。

### F-158 [架构 / P2] BackgroundHostedService.cs:118-144（ChunkCleanup 直接 db.ChunkedUploads.Where + File.Delete(s.TempPath) + db.ChunkedUploads.Remove）；而 Server.Core IChunkedUploadService 已有 CleanupIncompleteSessionsAsync 与 SafeDeleteTemp

- **问题**：Host 层 BackgroundHostedService.ChunkCleanup 直接操作 DbContext 与 File.Delete，绕过了 Core 的 IChunkedUploadService（该服务已有 CleanupIncompleteSessionsAsync + SafeDeleteTemp 封装超时/临时文件语义），Host 与 Core 各维护一套『分块会话超时清理』领域逻辑。
- **为何阻碍使命**：『领域逻辑进 Core，Host 只做宿主调度』——清理分块会话是领域行为，应归 IChunkedUploadService 单一实现；Host 直碰 DbContext+File 使清理策略在两层重复，改一处漏一处即并发/孤儿文件不一致（CLAUDE.md 7.1/7.3 高危区）。
