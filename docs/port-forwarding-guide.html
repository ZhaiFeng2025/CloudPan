CloudPan 路由器端口转发配置指南

手把手：把家庭局域网里的 CloudPan 服务端暴露到公网，实现外出也能同步文件。

适用版本
v1.0.0 正式版
HTTP 服务端口
TCP 8443
局域网发现端口
UDP 8450 无需公网转发
传输协议
HTTP 未启用 TLS
⚠️ 开始之前，请务必读完这一段 CloudPan v1.0 服务端监听 TCP 8443，且为纯 HTTP（无 TLS/HTTPS）。把 8443 直接暴露到公网意味着：账号 Token 和文件内容将以明文在互联网上传输，任何抓包者都能看到；同时端口会暴露给全网扫描器，面临暴力破解和漏洞探测风险。

强烈建议先评估第 0 步的替代方案（内网穿透 / VPN / 反向代理 + HTTPS）。若你的需求只是"出门在外临时取个文件"，使用 Tailscale / WireGuard 这类零配置组网方案通常比端口转发更安全、更省事。只有当你确实需要任意设备免客户端直接通过公网访问（例如把分享链接发给朋友），才继续按本指南配置端口转发。

0先想清楚——你真的需要公网端口转发吗？

端口转发只解决一个问题：让路由器外的设备（公网）直接访问内网的服务器。先对号入座：

你的需求推荐方案说明
只在家庭局域网内同步 无需任何配置 局域网内用 http://192.168.x.x:8443 直接访问，端口转发完全不需要。
出门在外，自己的手机/笔记本取文件 推荐：内网穿透 / VPN Tailscale、WireGuard、ZeroTier、frp 均可。加密通道，不用暴露公网端口，比端口转发安全得多。
把分享链接 /share/xxx 发给朋友（对方免登录） 需要端口转发 对方浏览器直接访问公网地址，无法装 VPN 客户端，只能走端口转发。此时请务必叠加第 8 节的安全加固。
安全底线 若选择端口转发，至少要做到：不要使用默认/弱 Token、分享链接设置密码、有条件就在前面加一层 HTTPS 反向代理（Caddy/Nginx）。纯 HTTP 裸奔公网 = 把家庭网盘密码贴在大街上。

1确认要转发的端口

CloudPan 共使用两个端口（来源：shared-spec.json → config）：

端口协议用途需要公网转发吗
8443TCPHTTP API + WebSocket 同步 + 分享链接要 全部公网功能都走这一个端口
8450UDP局域网设备发现（CLOUDPAN_DISCOVER 广播）不要 UDP 广播不会穿越路由器，且公网无需发现
结论 只需在路由器上转发 一条 TCP 规则：外部 8443 → 服务器内网 IP:8443。不需要转发 8450。WebSocket 同步与 HTTP API 共用 8443，不用额外开端口。
关于 /pair 和 /admin 配对页 /pair 与管理面板 /admin 在本项目设计中仅允许 localhost 访问。端口转发到公网后，外网访问这两个地址仍会被拒绝——这是安全设计，不是配置问题。管理请始终在服务器本机进行。

2确认 Windows 防火墙已放行 8443

端口转发只负责把公网流量送进路由器，进入路由器后还要过 Windows 防火墙这一关。通常 install-service.bat 已自动添加规则，这里验证一遍：

在服务器上打开 命令提示符（管理员），运行：

# 查看是否已有 CloudPan 的入站放行规则
netsh advfirewall firewall show rule name=CloudPan

如果输出为空，手动添加一条：

# 放行 TCP 8443 入站（仅专用网络）
netsh advfirewall firewall add rule name=CloudPan protocol=TCP dir=in localport=8443 action=allow profile=private

再快速验证服务端确实在监听：

# 本机访问健康检查，应返回 JSON
curl http://localhost:8443/api/health

若返回类似 {"status":"ok"...} 的 JSON，说明服务正常、防火墙已放行，可以继续。

3查服务器局域网 IP 并固定它

端口转发规则必须指向服务器的内网 IP。在服务器上打开命令提示符，运行 ipconfig，找到当前所用网卡的 IPv4 地址：

ipconfig
# 例：无线局域网适配器 WLAN:
#     IPv4 地址 . . . . . . . . . . . . : 192.168.1.100

记下这个地址（例如 192.168.1.100）。

关键：必须固定内网 IP，否则规则会失效 家用路由器默认用 DHCP 自动分配 IP，重启后服务器的内网 IP 可能改变，届时转发规则会指向错误设备。固定方法（二选一）：
  • 推荐：在路由器后台把服务器的 MAC 地址加入「DHCP 静态分配 / IP 与 MAC 绑定 / 地址保留」，固定为当前 IP。
  • 或在服务器「网络设置 → 更改适配器选项 → 属性 → IPv4」里改为静态 IP（需避开路由器 DHCP 分配池）。
查看服务器网卡 MAC 地址：ipconfig /all 里的「物理地址」。

4确认宽带是公网 IPv4（CGNAT 检测）

端口转发要求路由器有公网 IPv4 地址。国内部分运营商（尤其是没有单独拉公网 IP 的家庭宽带）会使用 NAT（CGNAT / 大内网），此时你的"公网 IP"其实仍是运营商内部的私有地址，路由器根本收不到外部连接，转发无从谈起。

怎么检测自己是不是大内网？

  1. 用 手机流量（关 WiFi）访问 myip.ipip.net 或 ip.cn，记下出口公网 IP。
  2. 登录路由器后台，找到「WAN 口状态 / 上网信息」，查看 WAN IP。
  3. 比较两者：
    • 一致 → 公网 IP，继续
    • 不一致，且路由器 WAN IP 是 100.64.0.0/10、10.x.x.x、172.16-31.x.x、192.168.x.x 等私有段 → CGNAT 大内网
如果是大内网，怎么办？
  • 联系运营商申请公网 IPv4（电信一般可致电 10000 申请，联通 10010，移动视地区而定），免费或低门槛。
  • 或改用 IPv6：多数宽带默认有公网 IPv6，可给服务器配 IPv6 + 路由器放行，然后走 http://[公网IPv6]:8443（IPv6 没有"转发"概念，是防火墙放行，此处不展开）。
  • 或放弃端口转发，用第 0 步的内网穿透方案（frp / Tailscale 等），它们不依赖公网 IP。

6配置端口转发规则

核心概念：端口转发 = 「外部端口（公网访问时用的端口）」 + 「内部 IP + 内部端口（转发到谁）」。不同品牌菜单名称不同，但填的字段是一样的：

功能名称转发规则名 / 服务名：CloudPan（随意）
外部端口（公网端口）8443（若运营商封此端口可改外部端口，见下）
内部 IP第 3 步记下的服务器内网 IP，如 192.168.1.100
内部端口8443（必须与 CloudPan 监听端口一致）
协议TCP（只转发 TCP，不需要 UDP 8450）

各品牌菜单位置

品牌入口路径（大致）
TP-LINK「转发规则 / 虚拟服务器」→ 添加，或「应用管理 → 虚拟服务器」
小米「高级设置 → 端口转发」→ 添加规则
华为「更多功能 → 网络设置 → 端口映射」
华硕「WAN → 虚拟服务器/端口转发」（Virtual Server / Port Forwarding）
Tenda 腾达「高级设置 → 虚拟服务器」
OpenWrt「Network → Firewall → Port Forwards」→ 添加，protocol=tcp, dest port=8443, internal ip=192.168.1.100:8443

填写完成后保存 / 应用，规则即生效。

运营商封锁常见端口 国内很多运营商封锁 80 / 8080 / 443 等常用端口。8443 通常不受影响；若外部访问 8443 超时且已排查其他原因，可尝试把「外部端口」改成 18443、8843 等非常规端口（内部端口保持 8443 不动），公网地址变成 http://公网IP:18443。

进阶：光猫桥接

若光猫是路由模式（自己拨号 + 分配 IP），且路由器也开了 NAT（双重 NAT），转发可能不生效。建议把光猫改桥接模式、让路由器拨号（需向运营商要宽带账号密码），只在一层设备上做端口转发。此项涉及光猫超级管理员权限，如遇困难可联系运营商装维。

7从公网验证配置是否成功

不要用 WiFi 下的电脑测——WiFi 内访问公网 IP 会走 NAT 回环，不能真实反映公网可达性。请用手机流量（关掉 WiFi）测试：

  1. 确认公网 IP：见第 4 步查到的出口 IP（或已配好的域名）。
  2. 手机浏览器打开 http://公网IP:8443/api/health。
  3. 结果判断：
    • 看到 {"status":"ok"...} 等 JSON → 成功！转发已生效
    • 一直转圈 / 超时 → 失败，对照下方故障排查表

也可以用电脑上在线端口检测工具（浏览器搜索"端口扫描/端口检测 在线"，输入公网 IP 和 8443），它会从外部向你的 IP 发探测包，结果更直观。

转发成功后 出门在外访问分享链接 http://公网IP:8443/share/分享ID 即可。客户端和 WebSocket 同步同样走 8443，无需额外配置。

8配置 DDNS（公网 IP 会变时）

家庭宽带公网 IP 通常是动态的（重启光猫/隔段时间就变），IP 一变，之前收藏的地址就失效。DDNS（动态域名）把「固定域名 → 你的当前公网 IP」自动绑定，之后只需记域名。

步骤

  1. 注册一个 DDNS 域名：国内常用花生壳（oray.com）、Dynu（免费）、No-IP（免费）；或使用阿里云/腾讯云域名 + DDNS 脚本。
  2. 在路由器后台 → 高级设置 → 动态 DNS (DDNS) 填入账号和域名，启用。路由器会自动更新 IP。
  3. 若路由器不支持该服务商，可在服务器上用官方客户端或脚本定时上报公网 IP。

配置完成后，公网访问地址变成 http://你的域名:8443，IP 再变也不用改。

9在客户端里连接

客户端（WinForms / Android 原型）连接公网服务端时，只需把「服务端地址」填成公网地址即可，Token 不变：

# 公网 IP 直连
CloudPan.Client.exe http://你的公网IP:8443  C:\CloudPan  <token>

# 有 DDNS 域名
CloudPan.Client.exe http://你的域名:8443  C:\CloudPan  <token>
注意 在局域网内时建议继续用 http://192.168.x.x:8443（不走公网、更快更稳）；出门在外再切到公网地址。UDP 发现（8450）只在局域网有效，公网连接请手动填写地址。

安全加固清单（强烈建议逐项执行）

再次强调 当前版本是纯 HTTP，公网明文传输。以下每一项都能显著降低风险，但最稳妥的做法仍是第 0 步的内网穿透/VPN 方案。
  1. 更换强 Token：不要使用默认 Token。Token 位于服务器同步目录 %USERPROFILE%\CloudPan\.cloudpan\token.txt，重新生成后分发到各客户端。
  2. 分享链接设密码：创建分享时启用密码保护，防止链接被搜刮/转发。
  3. 不要转发到默认常用端口：外部端口用非常规端口（如 18443）可避开大量无差别扫描。
  4. 保持限流开启：项目默认已启用每设备每分钟 60 次 API 调用限流（文件上传/下载不计入），无需额外配置，但请勿在生产环境关闭。
  5. 及时更新：关注 v1.1+ 的自动更新与 HTTPS 支持，升级后优先启用 TLS。
  6. 前置 HTTPS 反向代理（进阶）：在服务器上部署 Caddy/Nginx，把 443 转发到内网 8443 并自动签发证书，让公网走 HTTPS。此时需把路由器转发改为「外部 443 → 服务器:443（代理端口）」，本项目客户端填入 https://域名:443。
  7. 定期检查分享链接：在管理面板/API 中撤销不再使用的分享。
