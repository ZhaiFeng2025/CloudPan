1. 通用约定

1.1 基础信息

Base URLhttps://{host}:8443
内容类型请求/响应均为 application/json; charset=utf-8（文件上传除外）
字符编码UTF-8
时间格式ISO 8601 UTC（2026-07-27T14:30:00Z）
路径编码URL 中的文件路径需 encodeURIComponent，相对同步根的路径（如 /docs/report.docx → %2Fdocs%2Freport.docx）

1.2 请求头

Header值说明
AuthorizationBearer {token}所有 /api/* 端点必须携带（/share/* 除外）
X-Device-Id设备唯一标识所有 /api/* 端点必须携带
Content-Type见各端点JSON 或 multipart

1.3 成功响应格式

// 单条数据
{ "data": { ... } }

// 列表数据
{ "data": [ ... ] }

// 文件下载：直接返回文件流，响应头携带元信息

1.4 错误响应格式

{ "error": { "code": "CONFLICT", "message": "版本冲突：当前版本为 v5，你基于 v3", "details": { "currentVersion": 5, "yourBaseVersion": 3 } } }

2. 认证

2.1 认证流程

1客户端首次连接时，用户在界面输入服务端地址 + Token
2客户端执行 TLS 握手，服务端返回自签证书
3客户端展示证书指纹（SHA-256），用户确认后 pin 住。不匹配则拒绝连接
4所有后续请求在 Authorization: Bearer {token} 中携带 Token
5服务端对 Token 做 SHA-256 后与存储的哈希比对。不匹配 → 401

2.2 证书 Pin 指纹

客户端首次连接成功后，将服务端证书的 SHA-256 指纹持久化存储。后续每次 TLS 握手时校验。指纹变化 → 客户端本地拒绝连接并弹窗告警（可能是中间人攻击，也可能是服务端重新生成了证书）。此检查发生在 TLS 层，服务端无感知——不会有对应的 HTTP 错误码。

Android 实现：使用 OkHttp 的 CertificatePinner。首次连接时手动获取证书指纹，用户确认后调用 CertificatePinner.Builder().add(host, "sha256/xxx").build()。

2.3 Android 轮询模式

Android 端不使用 WebSocket（移动网络下长连接耗电且不稳定）。改为每 15 分钟发送 GET /api/files/tree?sinceVersion={本地maxVersion}&limit=100 查询增量变更。如有变更 → 触发下载或通知。轮询前先 ping GET /api/health 确认可达性。照片备份为独立 Foreground Service，不受轮询间隔影响。

3. 文件操作

GET/api/files/tree获取文件树（含哈希和版本信息）
参数位置必填说明
sincequery否ISO 8601 UTC 时间戳。仅返回此后有变更的文件。不传则返回全量。推荐改用 sinceVersion
sinceVersionquery否（推荐）全局单调版本号。仅返回版本号 > sinceVersion 的文件变更。比时间戳更可靠（无时钟偏差问题）
pathquery否子目录路径。仅返回该目录下的内容
limitquery否每页条数（默认 5000，最大 10000）。超出则分页
cursorquery否分页游标（上次响应中的 nextCursor）。不传则返回第一页

响应 200：

{
  "data": [ ... ],
  "nextCursor": "eyJwYXRoIjoiL3Bob3Rvcy96ei5qcGcifQ==",
  "hasMore": true,
  "maxVersion": 15420
}
分页：如果 hasMore=true，客户端用 cursor=nextCursor 请求下一页。sinceVersion 推荐用法：客户端本地记录 maxVersion，下次请求时传 sinceVersion=maxVersion，仅拉取增量变更。首次同步传 sinceVersion=0 获取全量。
POST/api/files/upload上传文件
参数位置必填说明
filemultipart是文件内容（二进制流）
pathmultipart是相对路径，如 "/docs/report.docx"
baseVersionmultipart是客户端基于哪个版本修改。首次上传传 0
lastModifiedmultipart是文件最后修改时间（ISO 8601 UTC）

Content-Type: multipart/form-data

响应 200（成功，无冲突）：

{
  "data": {
    "path":    "/docs/report.docx",
    "version": 13,
    "hash":    "d3b0c44298fc1c15...",
    "size":    245800,
    "conflictResolved": false
  }
}

响应 200（上传方在冲突中胜出）：

{
  "data": {
    "path":    "/docs/report.docx",
    "version": 13,
    "hash":    "d3b0c44298fc1c15...",
    "size":    245800,
    "conflictResolved": true,
    "conflictCopyPath": "/docs/report_冲突_20260727_143000.docx"
  }
}

响应 409（冲突）：

{
  "error": {
    "code":    "CONFLICT",
    "message": "版本冲突",
    "details": {
      "currentVersion":  13,
      "yourBaseVersion": 11,
      "conflictWinner":  "server",
      "conflictCopyPath": "/docs/report_冲突_20260727_143000.docx"
    }
  }
}
冲突处理流程：客户端收到 409 → 服务端已保留冲突副本 → 客户端应拉取最新版本，然后重新上传（此时 baseVersion = currentVersion）。如果服务端判定上传方胜出（lastModified 更新），则 conflictWinner = "uploader"，服务端直接更新当前版本，旧版本存为副本。此时返回 200 而非 409。
GET/api/files/download?path=...下载文件
参数位置必填说明
pathquery是文件相对路径（需 URL 编码）
versionquery否指定下载历史版本。不传则下载当前版本

响应 200：文件二进制流（Content-Type: application/octet-stream）

响应头说明
X-File-Hash文件 SHA-256（客户端下载后必须校验）
X-File-Version版本号
X-File-Size字节数
X-File-Modified最后修改时间
Content-Dispositionattachment; filename="report.docx"
POST/api/files/delete删除文件
参数位置必填说明
pathbody是文件/文件夹相对路径
baseVersionbody是基准版本号（用于冲突检测）
→ { "path": "/docs/old.docx", "baseVersion": 5 }
← 200 { "data": { "path": "/docs/old.docx", "deletedVersion": 6 } }
← 409 冲突（删除时文件已被修改）
// 删除文件夹 → 递归删除全部子文件和子文件夹。每个子文件产生独立的版本记录
POST/api/files/move移动或重命名文件/文件夹
参数位置必填说明
oldPathbody是原路径
newPathbody是新路径
baseVersionbody是基准版本号
→ { "oldPath": "/docs/draft.docx", "newPath": "/docs/final.docx", "baseVersion": 3 }
← 200 { "data": { "oldPath": "/docs/draft.docx", "newPath": "/docs/final.docx", "version": 4 } }
POST/api/files/mkdir创建文件夹
→ { "path": "/docs/新项目" }
← 200 { "data": { "path": "/docs/新项目" } }
← 409 路径已存在
POST/api/files/upload/chunk大文件（≥10MB）分块上传
参数位置必填说明
pathmultipart是文件路径
chunkIndexmultipart是块索引（从 0 开始）
totalChunksmultipart是总块数
chunkHashmultipart是当前块的 SHA-256
fileHashmultipart是完整文件的 SHA-256（仅第一块携带）
baseVersionmultipart是同普通上传
lastModifiedmultipart是同普通上传
chunkmultipart是块数据（≤4MB）

响应 200（块已接收，等待下一块）：

{ "data": { "status": "chunk_received", "chunkIndex": 3, "totalChunks": 10 } }

响应 200（最后一块，上传完成）：

{ "data": { "status": "complete", "path": "/photos/large.jpg", "version": 5, "hash": "abc123...", "size": 52428800 } }

响应 200（块哈希匹配，跳过）：

{ "data": { "status": "chunk_skipped", "chunkIndex": 3 } }
上传流程：① 客户端计算所有块的哈希 ② 调用 GET /api/files/upload/chunk/status 查询服务端已有块 ③ 仅上传缺失的块 ④ 第一块携带 fileHash ⑤ 服务端比对：如果该 fileHash 与服务端当前版本哈希相同 → 跳过全部上传 ⑥ 所有块收齐后 → 服务端合并、校验 fileHash、原子替换。
GET/api/files/upload/chunk/status查询分块上传进度（用于断点续传）
参数位置必填说明
pathquery是文件路径
fileHashquery是完整文件的 SHA-256
totalChunksquery是总块数
← 200 { "data": { "missingChunks": [3, 5, 7], "serverFileHash": "abc..." } }
断点续传逻辑：① serverFileHash == 请求的 fileHash → 文件内容未变，全部跳过 ② missingChunks 为空 → 所有块已在服务端，合并即完成 ③ missingChunks 非空 → 仅上传数组中列出的块索引。如果文件路径在服务端不存在（首次上传），返回所有块缺失。

4. 版本管理

GET/api/versions?path=...获取文件的历史版本列表
参数位置必填说明
pathquery是文件路径（需 URL 编码）
← 200 {
  "data": [
    { "version": 12, "hash": "abc...", "size": 245800, "timestamp": "2026-07-27T14:30:00Z", "deviceName": "张三的笔记本" },
    { "version": 11, "hash": "def...", "size": 245760, "timestamp": "2026-07-26T09:15:00Z", "deviceName": "台式机" }
  ]
}
仅返回 P2 版本历史范围内保留的版本（默认 5 个）。列表按版本号降序排列。
POST/api/versions/restore回滚到指定历史版本
参数位置必填说明
pathbody是文件路径
versionbody是要回滚到的版本号
→ { "path": "/docs/report.docx", "version": 11 }
← 200 { "data": { "path": "/docs/report.docx", "newVersion": 13, "hash": "def...", "size": 245760 } }
回滚操作本身创建新版本（不删除中间版本）。version 12 → 回滚到 11 → 当前版本变为 13（内容 = v11）。

5. 缩略图与搜索

GET/api/thumbnails?path=...&size=200获取图片缩略图
参数位置必填说明
pathquery是图片文件路径（需 URL 编码）
sizequery否最大边长（像素）。默认 200。缓存于 .thumbnails/ 目录

服务端首次请求时生成缩略图并缓存。后续请求直接返回缓存文件（image/jpeg）。

GET/api/files/search?q=...按文件名搜索
参数位置必填说明
qquery是搜索关键词（LIKE 匹配文件名，最少 2 字符）。不搜索文件内容
limitquery否最大结果数（默认 50）
← 200 { "data": [ { "path": "/docs/report.docx", "type": "File", "size": 245800 } ] }

6. 分享链接

POST/api/shares创建分享链接（需 Token 认证）
参数位置必填说明
pathbody是要分享的文件路径。不支持分享文件夹——如需分享多文件，先打包为 ZIP
expireHoursbody是有效时长（小时）。0 = 永不过期
passwordbody否访问密码。不传 = 无密码
maxDownloadsbody否最大下载次数。不传 = 不限
→ { "path": "/photos/family.jpg", "expireHours": 24, "password": "1234", "maxDownloads": 10 }
← 200 { "data": {
    "shareId":  "a1b2c3d4e5f6",
    "url":      "https://123.45.67.89:8443/share/a1b2c3d4e5f6",
    "expiresAt": "2026-07-28T14:30:00Z"
  } }
GET/share/{shareId}访问分享链接（无需 Token）

流程：

1浏览器访问 URL → 服务端返回轻量 HTML 页面（下载页或密码输入页）
2若无需密码：页面显示文件名、大小，点击「下载」→ GET /share/{shareId}/download → 返回文件流
3若需密码：页面显示密码输入框 → 密码通过 query string 发送（GET /share/{shareId}/download?password=xxx）。密码验证通过返回文件流，失败返回 401。无 Cookie、无 session
为什么不用 Cookie：家庭工具不需要 session 管理。分享链接的密码保护是轻量级屏障（防止链接被意外传播），非高安全性场景。query string 传递密码在 HTTPS 下是加密的（TLS 保护整个 URL 路径+参数）。
DELETE/api/shares/{shareId}撤销分享链接（需 Token 认证）
← 200 { "data": { "shareId": "a1b2c3d4e5f6", "revoked": true } }
← 404 分享链接不存在或已过期

8. 健康检查

GET/api/health服务端健康状态（无需 Token）
← 200 { "status": "ok", "version": "1.0.0", "uptimeSeconds": 86400 }
客户端可用于：① 启动时检测服务端是否可达 ② Android 轮询时先 ping 此端点（极轻量，无 DB 查询）③ 展示「上次连接成功时间」

9. WebSocket 实时通知

8.1 连接

端点wss://{host}:8443/ws
认证连接建立后，客户端在第一条消息中发送 {"type":"auth","token":"xxx","deviceId":"d1-xxx"}。服务端验证后回复 {"type":"auth_ok"} 或 {"type":"auth_error","message":"..."} 再断开。Token 不在 URL 中传递——避免写入服务器日志
心跳客户端每 30 秒发送 {"type":"ping"}，服务端回复 {"type":"pong"}。60 秒无心跳 → 服务端断开
重连断开后客户端指数退避重连（1s → 2s → 4s → ... max 60s）。重连成功后重新认证，然后执行全量文件树比对，比对完成后查询比对期间的新变更并追赶（消除时间窗口遗漏）

8.2 事件定义

PUSHfile_changed服务端 → 客户端：文件内容变更
{
  "type": "file_changed",
  "path": "/docs/report.docx",
  "newVersion": 13,
  "deviceId": "d1-xxx",
  "deviceName": "台式机",
  "timestamp": "2026-07-27T14:30:00Z"
}
PUSHfile_deleted服务端 → 客户端：文件已删除
{
  "type": "file_deleted",
  "path": "/docs/old.docx",
  "deviceId": "d2-xxx",
  "deviceName": "笔记本",
  "timestamp": "2026-07-27T14:31:00Z"
}
PUSHfile_renamed服务端 → 客户端：文件重命名/移动
{
  "type": "file_renamed",
  "oldPath": "/docs/draft.docx",
  "newPath": "/docs/final.docx",
  "deviceId": "d1-xxx",
  "deviceName": "台式机",
  "timestamp": "2026-07-27T14:32:00Z"
}
PUSHconflict服务端 → 客户端：冲突已自动解决
{
  "type": "conflict",
  "path": "/docs/report.docx",
  "winnerVersion": 13,
  "winnerDeviceId": "d2-xxx",
  "winnerDeviceName": "小明的笔记本",
  "winnerModifiedAt": "2026-07-27T14:30:00Z",
  "loserPath": "/docs/report_冲突_20260727_142500.docx",
  "timestamp": "2026-07-27T14:33:00Z"
}

8.3 客户端推送范围

file_changed推送给所有在线设备（变更方自己除外）。所有设备需要拉取新内容
file_deleted推送给所有在线设备（删除方自己除外）
file_renamed推送给所有在线设备（操作方自己除外）
conflict仅推送给冲突涉及的两台设备（上传方 + 中心节点本地用户）。不广播给无关设备

10. 错误码

HTTPcode说明客户端行为
400BAD_REQUEST请求参数缺失或格式错误检查参数后重试
401UNAUTHORIZEDToken 无效或缺失提示用户检查 Token
404NOT_FOUND文件/路径不存在刷新本地文件树
409CONFLICT版本冲突（上传/删除时 baseVersion 过期）拉取最新版本，处理冲突后重试
413PAYLOAD_TOO_LARGE单次请求体超过 5MB（非分块上传场景）改用分块上传
429RATE_LIMITED请求频率过高（默认：每设备 60 次/分钟 API 调用；文件上传/下载不计入）退避后重试。响应头 Retry-After 指示等待秒数
500INTERNAL_ERROR服务端内部错误退避重试。持续失败通知用户
503SERVICE_UNAVAILABLE服务端维护中/过载退避重试

11. 数据类型参考

10.1 FileState 枚举

Synced已同步，本地与服务端一致
Modified本地已修改，待上传
Deleting本地已删除，待同步删除至服务端
CloudOnly仅云端存在，本地未下载（选择性同步场景）
Downloading正在从服务端下载
Uploading正在上传至服务端
Conflict处于冲突状态（用户未处理）

10.2 版本号规则

初始版本文件首次上传后版本号为 1
递增每次修改上传成功后 +1。服务端分配，客户端从响应中获取
baseVersion = 0表示「首次上传，不检查冲突」。仅用于新文件
版本号单调全局唯一，永不复用。即使文件被删除后重建，版本号继续递增

10.3 Token 格式

生成服务端首次安装时随机生成（64 字符十六进制 = 256 位熵）
存储服务端仅存储 SHA-256(Token)。客户端明文存储
传输Authorization: Bearer <token>。WebSocket 通过 query string
