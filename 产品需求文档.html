1. 系统约束与假设

以下约束是系统设计的硬边界。任一约束改变，需重新评估全部设计决策。

1.1 运行环境

服务端操作系统Windows 10/11（常开台式机，同时作为工作电脑使用）
客户端操作系统Windows 10/11（多台，轮换使用）；Android 10+
网络拓扑各设备不在同一局域网。所有通信经互联网通过中心节点中转
公网可达性家庭宽带有公网 IPv4 地址（基本固定）。路由器可配置端口转发
域名不使用。客户端通过公网 IP 直连

1.2 数据特征

文件类型文档（Office / PDF / 纯文本）+ 图片。无代码仓库
总量数百 GB
用户数1-5 人（家庭成员）。无权限体系——所有人看到所有文件。共享一个家庭 Token
设备数多台 Windows + 多台 Android。常开台式机为同步中心

1.3 关键假设

设备使用模式多设备轮换使用。多人可能同时编辑不同文件，同一文件的并发编辑概率中等
时钟同步所有 Windows 设备开启自动时间同步。设备间时钟偏差 < 5 秒
版本历史需求低频（偶尔误改误删时找回）。非核心功能
文件修改模式Office 文档修改后整体重写（ZIP 结构）；图片仅新增不修改；PDF/文本局部修改

2. 产品定义

2.1 产品描述

CloudPan 是一个自托管、家庭共享、Windows 原生的文件同步系统。在一台常开 Windows 电脑上运行同步中心节点，家庭成员（1-5 人）的多台 Windows 设备和 Android 手机通过互联网自动同步文件。所有人共享同一文件空间，无权限隔离。

2.2 核心价值

数据主权所有文件存储在自有硬件上，零第三方接触
跨设备同步Windows 设备间文件自动双向同步；Android 照片自动备份
零运维SQLite 嵌入式数据库，无需独立数据库服务。安装即用
原生体验Windows 原生 UI，不依赖 Docker/WSL/虚拟机/浏览器

2.3 技术栈

组件选型
服务端 + Windows 客户端语言C# / .NET 8 LTS
Windows 桌面 UIWinUI 3
服务端运行形态Windows Service（后台）+ 托盘程序（管理界面）
服务端 HTTPASP.NET Core 8 (Kestrel)
Android 语言Kotlin
Android 本地存储Room (SQLite ORM)
Android 网络OkHttp + Retrofit
数据库SQLite + Entity Framework Core
通信协议REST (HTTPS) + WebSocket
HTTPS 证书首次启动自动生成自签证书，客户端 pin 指纹
文件监控FileSystemWatcher + 定时扫描兜底
打包MSIX (Windows) / APK (Android)

6. 同步模型

6.1 同步根

每台设备指定一个文件夹作为同步根。该文件夹即用户的云盘。文件夹之外的文件不受同步系统影响。

6.2 行为规则

放入文件/文件夹放入同步根 → 自动上传至中心节点 → 推送通知至其他在线设备
修改文件内容变更被检测 → 自动上传新版本
删除同步根内删除 → 中心节点删除 → 其他设备同步删除（P3 回收站可拦截）
移出将文件移出同步根 = 删除。中心节点删除，其他设备同步删除
重命名文件/文件夹重命名 → 同步为 rename 操作（非 delete + create）
路径独立各设备同步根路径独立。台式机 D:\Sync，笔记本 C:\Sync 不要求一致

6.3 变更检测

主通道FileSystemWatcher（ReadDirectoryChangesW 封装）。变更后 1-2 秒内捕获
兜底通道定时全量扫描（默认间隔 5 分钟）。扫描后本地文件树哈希与中心节点比对，不一致则触发同步。此为正确性保证——FSWatch 可能因缓冲区溢出丢失事件，定时扫描确保最终一致

6.4 传输策略

文件 < 10MB整文件传输。覆盖绝大多数文档和图片
文件 ≥ 10MB4MB 分块传输 + 断点续传。块哈希比对，仅传差异块
变更检测上传前 SHA-256 比对。哈希 + 文件大小均相同 → 跳过（文件未变更）
下载校验下载完成后 SHA-256 校验。不匹配则重传
原子写入服务端先写 .tmp 临时文件 → 校验 → 通过后原子 rename
大文件哈希后台线程计算 SHA-256，不阻塞扫描主循环

6.5 冲突处理

多人共享同一文件空间，冲突概率高于单人场景。处理机制不变，但需更明确的通知。

检测客户端上传时携带基准版本号。服务端比对——基准版本 ≠ 当前版本 → 冲突
判定比较两版本的文件最后修改时间。较新者 → 当前版本；较旧者 → 冲突副本。同时间则保留两版都不覆盖
副本命名文件名_冲突_YYYYMMDD_HHMMSS.ext。通知中说明冲突原因和处理结果
通知冲突涉及的文件所在路径的设备收到通知（含中心节点本地）。不广播给无关设备。通知中标注优胜方设备名和修改时间，用户可手动从副本恢复

6.6 崩溃恢复

启动时执行一致性修复扫描：

孤儿文件（磁盘有，DB 无）重新索引。写入 DB 并标记为新增，同步至其他设备
悬空引用（DB 有，磁盘无）标记为「需重新下载」。不自动删除 DB 记录——等待下次同步时从中心节点拉取
权威来源冲突时文件系统为准。磁盘上实际存在的文件视为事实

6.7 客户端状态机

空闲 ──→ 扫描变更 ──→ 比对哈希 ──→ 传输(上传/下载) ──→ 冲突检查 ──→ 应用变更 ──→ 空闲 ↑ │ └──────────────────── 等待下次事件/定时器 ──────────────────────────────────────┘ 错误分支： 网络断开 → 传输队列持久化(SQLite)，挂起等待。恢复后 FIFO 处理 磁盘满 → 暂停同步，通知用户 文件锁定 → 跳过，下轮重试。连续 10 次失败后通知 服务端错 → 指数退避重试(1s→2s→4s→...max 5min)。持续失败通知 外部删除 → 视为用户主动删除，同步至中心节点

7.1 存储架构

8. 通信协议

8.1 协议栈

传输加密TLS 1.3（自签证书，客户端 pin 指纹）
应用认证预置 Token（SHA-256 哈希存于服务端）
文件传输HTTPS REST（multipart upload / stream download）
元数据操作HTTPS REST（JSON）
实时通知WebSocket（仅推送变更事件，不含文件内容）
Android 后台定时 HTTPS 轮询（15 分钟间隔）

8.2 REST API 端点（概要）

方法路径用途
POST/api/files/upload上传文件（multipart: file + baseVersion + lastModified）
GET/api/files/download?path=...下载文件（stream）
GET/api/files/tree获取文件树（含哈希、版本、状态）
POST/api/files/delete删除文件（携带 baseVersion）
POST/api/files/move移动/重命名
GET/api/versions?path=...获取文件版本列表
POST/api/versions/restore回滚至指定版本
GET/api/devices已注册设备列表
GET/api/health服务端健康检查
POST/api/shares创建分享链接（需 Token：path, expireHours, password?, maxDownloads?）
GET/share/{shareId}分享下载页/下载流（无需 Token。有密码则先验证）

8.3 WebSocket 事件

事件类型载荷触发条件
file_changed{ path, newVersion, deviceId }文件内容变更已确认
file_deleted{ path, deviceId }文件删除已确认
file_renamed{ oldPath, newPath, deviceId }文件重命名/移动已确认
conflict{ path, winnerVersion, winnerDeviceId, winnerModifiedAt, loserPath }冲突已自动解决。载荷含优胜方设备 ID 和修改时间，客户端可展示「谁的修改被保留」

8.4 重连一致性

WebSocket 断开重连流程：记录重连时间戳 → 执行全量文件树比对 → 比对完成后查询「比对期间产生的新变更」→ 如有则增量追赶。确保零时间窗口遗漏。

9. 安全模型

9.1 威胁模型

信任边界：中心节点 = 可信（自有硬件）。网络 = 不可信（公网）。客户端设备 = 可信（自用设备）。

9.2 安全措施

层级措施
传输TLS 1.3，自签证书。客户端首次连接展示证书指纹，用户确认后 pin 住。后续指纹不匹配则拒绝连接
认证一个家庭共享 Token。服务端存储 Token 的 SHA-256 哈希（不存明文）。所有客户端使用同一 Token。Token 泄露 → 重新生成并分发给全家人
攻击面端口 8443 暴露两条路径：① /api/* 需 Token 认证（同步操作）② /share/* 无需 Token（分享下载，以分享 ID + 可选密码鉴权）。Web 管理面板绑定 localhost
Token 展示托盘菜单默认遮罩 Token，点击「显示」后才可见。二维码和 Token 明文不同时展示
证书生成首次启动自动生成 CA 根证书 + 服务端证书。用户零操作
分享链接证书分享对象通过浏览器访问自签证书站点时，浏览器会显示安全警告。此为已知限制——家庭使用场景下分享对象通常是可信任的人，可手动跳过警告。远期可配合域名方案升级为正式证书

9.3 不在威胁模型内

  • 物理接触攻击（攻击者坐在你的台式机前）
  • 操作系统级漏洞（假设 Windows 和 Android 系统本身安全）
  • 量子计算攻击（SHA-256 碰撞在经典计算下物理不可能）

10. 外网访问

10.1 方案

拓扑路由器端口转发（8443 → 台式机 8443）+ 客户端直连公网 IP
前置条件① 台式机固定局域网 IP ② 路由器添加端口转发规则 ③ 查询公网 IP 填入客户端
IP 变动基本固定，偶尔重启光猫变化。变动后手动更新客户端配置。接受此风险，不引入 DDNS/域名

10.2 初始化步骤

1台式机设置固定局域网 IP（根据实际网段）
2路由器：外部端口 8443 → 台式机固定 IP:8443
3客户端填入当前公网 IP（IP 变动时重复此步）

11.4 首次同步时间估算

假设500GB 数据 / 家庭上行 30Mbps（~3.75MB/s）
理想~38 小时
实际~2-3 天（协议开销 + 小文件停顿）

14. 风险登记

ID风险影响缓解
R1台式机关机所有同步中断客户端持久化待同步队列，恢复后自动追赶。BIOS 设置通电自启
R2家庭上行带宽瓶颈多设备同步慢带宽限速 + 小文件优先。物理限制，软件无法根本解决
R3Android 后台被杀备份不及时Foreground Service + 引导关闭电池优化 + 15 分钟轮询非实时
R4台式机磁盘故障数据丢失超出本系统范围。建议用户使用 Windows 文件历史记录或定期手动备份
R5外网端口暴露被扫描/攻击自签证书 pinning + Token 认证 + 最小化攻击面。不知 Token 者连上端口也无法操作
R6文件路径兼容Android 显示异常服务端统一 Windows 兼容文件名规则。Android 端映射显示
R7SQLite 文件损坏元数据丢失SQLite WAL 模式。启动时执行完整性检查。建议定期备份 SQLite 文件
R8多用户并发冲突同一文件被两人同时修改时，一人修改会进入冲突副本冲突通知中标注最后修改人和时间。家庭成员沟通后手动恢复。远期可考虑自动合并纯文本文件
R9Token 共享泄露任何知道 Token 的人都能访问全部文件Token 仅限家庭成员。托盘菜单默认遮罩。泄露后服务端重新生成 Token 并分发给所有人
